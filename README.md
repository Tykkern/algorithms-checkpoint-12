# Контрольная точка 12: динамическое программирование на отрезках, сетках и деревьях

Практикум по алгоритмам. Шесть задач, решения на Java.

| № | Задача | Класс | Подход | Время | Память |
|---|---|---|---|---|---|
| 1 | Разбиение на палиндромы | `PalindromePartition` | ДП по префиксам + расширение от центров | O(n²) | O(n) |
| 2 | Маршруты по карте | `GridRoutes` | ДП по клеткам, одна строка | O(n·m) | O(m) |
| 3 | Несмежные станции в дереве | `TreeIndependentSet` | ДП на дереве (взята / не взята) | O(n) | O(n) |
| 4 | Объединение соседних групп | `MergeCost` | ДП по отрезкам | O(n³) | O(n²) |
| 5 | Путь с экранами | `ShieldPath` | ДП по (клетка, число экранов) | O(n·m·k) | O(m·k) |
| 6 | Связная часть дерева из k пунктов | `ConnectedSubtree` | рюкзак на дереве | O(n²) | O(n²) |

## Запуск

Нужен JDK 17 или новее, Gradle скачается сам через wrapper.

```
gradlew test                          # тесты
gradlew run -q --args="2" < input.txt # задача 2, ввод из файла
```

Номер задачи передаётся аргументом, входные данные читаются из stdin в формате
из задания, ответ печатается в stdout. Например, для задачи 5:

```
3 3 1
1 -5 2
-1 -100 3
4 -2 1
```

ответ `7`: путь по первой строке и последнему столбцу, экран закрывает `-5`.

На Windows проект лучше держать в папке без кириллицы в пути. Иначе Gradle
не находит тестовые классы (`ClassNotFoundException`), хотя они скомпилированы.

## 1. Разбиение на палиндромы

`parts[i]` - минимальное число палиндромов для префикса длины `i`. Каждый
палиндром `s[l..r]` даёт вариант `parts[r + 1] = parts[l] + 1`.

Таблица «является ли `s[l..r]` палиндромом» на 4000 символах заняла бы
16 миллионов ячеек. Вместо неё палиндромы перебираются расширением от центров.
Центр задаётся суммой `l + r`, суммы идут по возрастанию. У палиндрома, который
заканчивается в `l - 1`, сумма меньше `2l`, а у палиндрома, который начинается
в `l`, не меньше `2l`. Поэтому к моменту, когда используется `parts[l]`, это
значение уже окончательное. Палиндромов не больше n², памяти нужен один массив.

## 2. Маршруты по карте

В свободную клетку приходят сверху или слева, в заблокированную путей нет.
Строки обходятся сверху вниз, и хватает одной строки таблицы: до обновления
`ways[c]` хранит значение клетки сверху, а `ways[c - 1]` уже посчитано для
клетки слева. Всё по модулю 10^9 + 7. Если старт или финиш заблокирован,
0 получается сам собой.

## 3. Несмежные станции в дереве

Дерево подвешивается за станцию 1. Для каждой вершины считаются два числа:
лучший набор в её поддереве, если она взята, и если не взята.

```
take[v] = value[v] + сумма skip[child]
skip[v] = сумма max(take[child], skip[child])
```

Ответ `max(take[1], skip[1])`. Пустой набор разрешён, поэтому у листа `skip = 0`,
отрицательные ценности просто не берутся, и ответ не меньше нуля.

Дерево может быть цепочкой из 200 000 вершин, и рекурсивный обход переполнил бы
стек. Поэтому сначала строится порядок обхода в ширину, а вершины обрабатываются
в обратном порядке: дети раньше родителя. Списки смежности лежат в двух
массивах `int`, без объектов на каждую вершину.

## 4. Объединение соседних групп

`cost[l][r]` - минимальная стоимость собрать фрагменты `l..r` в одну группу.
Последнее объединение склеивает части `l..k` и `k + 1..r` и стоит сумму всех
фрагментов `l..r` независимо от того, как собирались части. Поэтому

```
cost[l][r] = min по k (cost[l][k] + cost[k + 1][r]) + sum(l..r)
```

Сумма отрезка берётся из префиксных сумм, отрезки считаются по возрастанию длины.
При n = 500 это около 2 * 10^7 шагов. Для больших n помогла бы оптимизация Кнута
до O(n²), здесь она не нужна.

## 5. Путь с экранами

`best[c][u]` - лучшая сумма пути до клетки текущей строки, если экран применён
не больше `u` раз. В клетку со значением `a` приходят сверху или слева с тем же
`u`, и `a` прибавляется. Если `a < 0`, есть второй вариант: закрыть клетку
экраном, взять путь, потративший не больше `u - 1` экранов, и прибавить 0.

Хранится одна строка таблицы, как в задаче 2. Ответ `best[m - 1][k]`. Экран
можно поставить и на стартовую, и на конечную клетку, отдельно это
обрабатывать не нужно.

## 6. Связная часть дерева из k пунктов

У любой связной части есть самая верхняя вершина `v`. `best[v][j]` - лучшая
сумма связной части из `j` вершин с верхней вершиной `v`. Сначала
`best[v] = {-, value[v]}`, затем каждый ребёнок `c` добавляется как в рюкзаке:
из его поддерева берётся связная часть с верхней вершиной `c` из `b` вершин
или ничего, и `best[v][a + b] = max(best[v][a] + best[c][b])`.

Ответ - максимум `best[v][k]` по всем вершинам. Таблица вершины не длиннее её
поддерева, поэтому все объединения вместе стоят O(n²): каждая пара вершин
встречается один раз, в их наименьшем общем предке. Ценности бывают
отрицательными, но взять нужно ровно `k` вершин, поэтому ответ может быть
отрицательным.

Обход такой же, как в задаче 3: обратный порядок BFS без рекурсии.

## Тесты

- на каждую задачу примеры, граничные случаи и сверка с перебором на случайных
  входах (все разбиения, пути, подмножества и порядки объединения);
- случайные деревья с перемешанными номерами вершин и случайной ориентацией рёбер;
- входы максимального размера из ограничений с таймаутом 5 секунд: цепочка
  из 200 000 вершин, карта 1000 на 2000 со сверкой с биномиальным коэффициентом,
  таблица 500 на 500 с 10 экранами;
- `MainTest` проверяет чтение ввода и формат вывода для всех шести задач.
